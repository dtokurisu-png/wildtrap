# WildTrap Godot migration — native terrain importer (step 2)

The `godot-migration` branch includes an actual native 3D scene built from
the **published WildTrap repository snapshot**, not an invented landscape.

## Open the result

Download / update the `godot-migration` branch *after* the validation job
finishes, and import `godot/project.godot` with Godot 4.7.2.

Press F5. The terrain, source zones and three original unmodified cave GLBs
will load. Right mouse drag rotates the inspection camera; mouse wheel zooms;
WASD moves the inspection focus. These are inspection controls, not the player.

## Exact source and native bake

- Original source data: `assets/terrain/wildtrap-mobile-world.json`
- Mirrored source document: `godot/data/world.json`, using the same Git blob
- Original cut algorithm: `adaptive-terrain-cuts.mjs`
- Original cliff geometry algorithm: `cliff-heightmap-geometry.mjs`
- Native terrain: `godot/data/terrain.wtmesh`, generated by
  `godot/tools/bake-world.mjs` and committed automatically by CI
- Zone masks: `godot/data/masks/*.png`, generated from the saved polygons
- Original images and GLBs are included using **the same Git blobs** as the
  original source assets, so there is no transcoding on import.
- Build report: `godot/data/world-build.json`
- The native Godot runtime does **not** require JavaScript, Node or Three.js.
  Node only runs in GitHub Actions to bake the original algorithm into an
  engine-native file.

## IMPORTANT — current fidelity boundaries

The accessible published JSON is `wildtrap-mobile-world.json`, **not a
verified copy of `wildtrap-escenario (4).json`**. Source comparison is still
required. Original model-sculpt operations and vertex anchors are preserved
as `godot/data/sculpt-ops.json` and `godot/data/sculpt-anchors.json` for the
next port, but are NOT applied to imported GLB meshes yet.

The terrain uses the saved source heights, source XY offsets and precise
polygonal cut algorithm. Plains cliff heightmap displacement is baked with
the original algorithm. The five ground textures and cliff body textures are
included, but current biome blending, missing alpha-detail decals and the
large hand-painted overlay are **not pixel-identical** to the Three.js editor.
Directional light, fog and shadows are early approximations for visual
inspection. Optimizing native colliders, full model sculpt reconstruction,
original material blending, and final player controls are separate stages.

Do not merge into `main` until source and visual parity are validated.

## Rebuild locally (only if changing the source JSON)

```bash
cd godot/tools
npm install --no-save pngjs@7.0.0
cd ../..
node godot/tools/bake-world.mjs
```

The GitHub workflow does this and checks import plus native scene boot. Never
reintroduce local browser storage as the authoritative world source.

## Step 2.1: native world in Godot's editor (without Play)

Open `res://scenes/main.tscn` and select the **3D** tab. The `World`
node now has an `@tool` script that reconstructs the terrain mesh, biome
shader and original GLB prefabs **in the editor**, using the same loader as
the runtime. Select `World` in the scene tree to find the Inspector toggle
**Vista previa** and its **Actualizar vista del mundo** button.

The mesh and GLB preview nodes are deliberately *transient* (no `owner`);
they will NOT be silently embedded into `main.tscn` when saving the scene.
Reopen `main.tscn` if another program changed source assets while the scene
was open, then click **Actualizar vista del mundo**. Use Godot's 3D orbit
controls to inspect the terrain. You may select `Camera3D` and enable
**Preview** to frame the level using the initial game camera.

In-game controls (character movement), procedural painting/gizmo editing,
spawn tools, and serialized inspector tools remain future milestones.
The Godot native editor preview does *not* save edits back to JSON yet.

## Step 2.2: WildTrap Editor dock in Godot

`res://addons/wildtrap_editor/` provides a native `EditorPlugin` dock.
It is enabled under `[editor_plugins]` in `project.godot`.

Open `scenes/main.tscn`, enter **3D**, and locate **WildTrap Editor**
in the right dock tabs (next to / below the Inspector, depending on layout).
The **Terreno** tab reports the generated mesh and can refresh its preview
or select `World`. The **Biomas** tab lists the source zones and displays a
temporary 3D outline of the selected polygon. The **Spawns** tab lists
player spawns and displays a marker in the scene. Both read exactly
`res://data/world.json` and do not generate fictional entries.

These tools inspect data and display non-persistent marker nodes (no scene
owner). No JSON, GLB or mesh file is written by panel controls. **Editing
and saving** biome/spawn properties is the next development phase. Never
treat selection or a preview marker as a saved change to the source.

## Native editor — persistent biome/zone distributions

Godot `godot/data/world.json` is now the canonical project world.
The earlier `assets/terrain/wildtrap-mobile-world.json` is a historical
web-editor snapshot, **not** a synchronisation target. Do not overwrite
Godot edits with it. The native geometry baker reads only the Godot JSON.

In **WildTrap Editor**, the **Biomas** buttons select all surfaces for that
biome with a temporary teal overlay. The **Zonas** tab lists all 16 saved
regions and cliff zones and provides the original five-biome permutations,
including the **Mountain is forbidden in Zona Este** rule and the original
neighbor restrictions. Click a possibility to change its biome masks in
the editor without pressing Play.

Changes remain **unsaved** until pressing **Guardar**. Save writes
`godot/data/world.json` and the five regenerated `godot/data/masks/*.png`
files directly into your cloned repository. Godot supports **Deshacer** and
**Rehacer** within the panel until save. Then commit/push from GitHub Desktop.

The canonical JSON is protected against an external change since the panel
loaded it. Reload (after resolving local changes) rather than overwriting
someone else's changes. GitHub Actions rebakes native cliff geometry after
you push. Changes to the cliff biome heightmap may therefore require that
GitHub bake before Play has the final updated geometry.

Spawn inspection is still read-only. Object placement, painting, editing of
the five polygon borders, geometry displacement in-editor, and native
player controls are separate stages. Original unknown JSON keys, geometry,
caves and sculpt metadata are not intentionally deleted.

## Godot panel usability: scrollable zones and real cliff previews

The native **WildTrap Editor** panel now uses one continuously scrollable
vertical page per tab. Zonas keeps its list of 16 preexisting polygons,
all distributions and the Previous/Next pager inside the same scroll view.
The separate nested lists and extra status explanations were removed.

**Mostrar acantilados** toggles a low-strength selection overlay on the
actual 11 stored cliff polygon footprints (including vertical wall fragments).
Selecting one cliff zone highlights that specific polygon rather than tinting
its entire parent biome. This is a read-only editor overlay; the physical
cliff height geometry and original JSON remain unchanged.

Biome highlighting is muted green instead of intense cyan, with just 14%
tint instead of 42%. Labels in the panel remain brief; detailed zone biome
names are available by hovering their buttons.


## Native spawn editor — direct 3D tools

Open main.tscn in Godot's 3D editor and open **WildTrap Editor > Spawns**.
Buttons **Punto**, **Área**, **Seleccionar** arm the *editor viewport*:
- **Punto**: choose Jugador/NPC/Árboles/Hierbas/Plantas/Rocas/Objetos/
  Criatura especial; click the real terrain to place. Slots J1–J6 are
  unique: placing an occupied player slot moves that slot instead of
  creating a duplicate.
- **Área**: click 3+ points on real terrain. Click the first point again,
  or click **Cerrar área**, to create a validated polygon. Self-crossings,
  tiny or degenerate polygons, and outside-map points are rejected.
- **Seleccionar**: click a saved point or inside an area to edit it. The
  side panel includes area name/type/biome/density/hidden, area vertices,
  exact X/Z for points, move-on-terrain buttons and delete.
- **Cancelar**: exits the viewport tool without writing pending vertices.
  Normal Godot orbit/zoom input is not intercepted unless a spawn tool is
  explicitly active. Other tabs disable spawn clicks.
- **Guardar** writes all changes to Godot's canonical world.json in the
  same locally cloned repository. Undo/Redo and external-change protection
  are shared with biome distributions.

The original characterSpawn, playerSpawn and spawnAreas JSON formats are
preserved. Non-character object/vegetation markers use the new
`kind:"spawnPoint",category:"..."` records, for native editing only.
The actual procedural population of trees, objects, NPC actors or creatures
is **not** implemented by this stage; placing a spawn defines where that
future game system may generate them. All spawn previews are transient editor
nodes, not game-world objects serialized to main.tscn.

## Source material parity: detail decals, cliff painting, handpaint underlay

The migration now copies 15 exact source **complementary** PNG blobs from the
unchanged `main` branch into `godot/assets/textures/details/`. All 15
saved detail1/detail2/detail3 slots are bound to a separate native transparent
material pass (seeded 3x3-cell spatial decals, preserving slot repeat/opacity,
biome contrast and saturation). The original terrain base remains separate
and unaffected if a decal texture is absent.

The five cliff PNGs use fresh **parent-biome cliff polygon masks** from
`godot/data/masks/cliff_<biome>.png`. Cliff walls are painted only on
steep geometry inside the saved cliff polygons, with individual saved color
repetition and intensity. Mountain may correctly have no such mask pixels
when no cliff belongs to the Mountain *parent* region.

`res://assets/textures/handpaint_reference.webp` is the original global
4K art, composited once across the terrain at 50% default strength with
grayscale overlay and white-paper suppression. Cliff walls are excluded via
slope blending. Open the **Biomas** tab to compare **Complementarias**,
**Hand painting** and **Acantilados (textura)** independently. The slider
changes handpaint preview opacity from 0–100%. These switches are
nonpersistent visual comparisons and do not alter world.json. More detailed
material settings/editing can be migrated after visual parity tests.

**Camera:** The Godot editor's own 3D orbit camera is *not* the game's
`Camera3D` in `bootstrap.gd`; it has no automatic terrain collider.
Use Godot editor's RMB free-look / Shift+F then WASD/Q/E and Alt to move
slowly near the ground, or Shift+middle mouse to pan the orbit target.
This lets you inspect patches at close range without relying on the large
orbit step distance. Full third-person player camera/collision is a separate
step, and does not yet exist in the native project.

## Native WildTrap Editor — the definitive five tabs

Open `scenes/main.tscn` and the **WildTrap Editor** right dock. All five
tabs are scrollable: **Biomas | Zonas | Spawns | Objetos | Texturas**.
Biomas now contains only biome selection; material controls are in Texturas.

**Objetos** lists the complete 15-item original prefab library (source
models are copied from the same repo, without changing `main`).
Choose a model in the palette, click **Colocar**, then click on the
terrain in the Godot 3D viewport. Select a placed model from the list
and change its X/Z, Y yaw (degrees), scale or (for the original three free
caves) absolute Y. **Seleccionar**, **Mover**, hide/show and remove operate
on the scene data with native undo/redo, then **Guardar** persists
`nodes[]` into `godot/data/world.json`. Native view models are transient
scene children and will not be duplicated inside `main.tscn`.
Earlier browser mesh sculpt/cut operations on old prefabs have not been
ported to Godot and are preserved as JSON only.

**Texturas** selects a biome and one of five slots: Suelo base,
Complementaria 1–3 or Acantilado. The image preview uses the verified
original PNG, and details may be switched among the 15 recovered RGBA
assets. Change repeats, opacity, biome contrast/saturation; press
**Aplicar material** to add that change to the project's undoable state.
Global Hand painting supports opacity, black/ink contrast, rotation and
eight blend modes, with **Aplicar hand painting** for persistence. Live
preview values in this tab affect only the current 3D editor view until
applied. Use the three comparison switches here to show or hide Details,
Hand painting and Cliff colors without changing the saved world data.

**Guardar** writes native project world.json; follow with Commit and
Push in GitHub Desktop. Do not modify the original browser files to edit
the new Godot version. The native scene view still uses the stock Godot
editor camera; it is not automatically terrain-collision constrained.

## Native playable Explorer 1 WT (F5)

The Godot editor still previews the saved World without pressing Play.
Press **F5** to start `scenes/main.tscn` in gameplay mode: the exact
`assets/explorador 1 wt.glb` is imported as
`godot/assets/models/explorador_1_wt.glb`; the Play-only controller
starts at the saved J1 `playerSpawn`, uses a 0.90m visual character and
capsule collision (radius 0.21, height 0.875).
Movement and third-person camera settings come from the existing
`playtest.mjs`: **WASD** and arrows camera-relative, **Shift** accelerates
from 1.90 to 3.00 units/sec, hold mouse button and drag to orbit,
and the camera follows ~2.55 units behind with shoulder offset 0.28.
The idle (source clip 3) and running (source clip 5) animation use in-place
root motion and blend in 0.16 sec. Terrain cuts and placed cave mesh
surfaces provide temporary Play-only physics colliders; these colliders
are not saved into main.tscn.

This is a first playable validation of the native Explorer. The separately
corrected Web animation encoded in `assets/animations/explorer-run-corrected.b64`
still needs a Godot-compatible retargeting/export step; the controller
currently uses the original fifth GLB animation rather than silently
substituting any other character. Advanced cave occlusion, mobile joystick,
and multiplayer are not part of this step.
