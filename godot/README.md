# WildTrap Godot migration — native terrain importer (step 2)

The `godot-migration` branch includes an actual native 3D scene built from
the **published WildTrap repository snapshot**, not an invented landscape.

## Open the result

Download / update the `godot-migration` branch *after* the validation job
finishes, and import `godot/project.godot` with Godot 4.7.2.

Press F5. The terrain, source zones and three original unmodified cave GLBs
will load. Right mouse drag rotates the inspection camera; mouse wheel zooms;
WASD moves the inspection focus. These are inspection controls, not the player.

## Exact source and native bake

- Original source data: `assets/terrain/wildtrap-mobile-world.json`
- Mirrored source document: `godot/data/world.json`, using the same Git blob
- Original cut algorithm: `adaptive-terrain-cuts.mjs`
- Original cliff geometry algorithm: `cliff-heightmap-geometry.mjs`
- Native terrain: `godot/data/terrain.wtmesh`, generated by
  `godot/tools/bake-world.mjs` and committed automatically by CI
- Zone masks: `godot/data/masks/*.png`, generated from the saved polygons
- Original images and GLBs are included using **the same Git blobs** as the
  original source assets, so there is no transcoding on import.
- Build report: `godot/data/world-build.json`
- The native Godot runtime does **not** require JavaScript, Node or Three.js.
  Node only runs in GitHub Actions to bake the original algorithm into an
  engine-native file.

## IMPORTANT — current fidelity boundaries

The accessible published JSON is `wildtrap-mobile-world.json`, **not a
verified copy of `wildtrap-escenario (4).json`**. Source comparison is still
required. Original model-sculpt operations and vertex anchors are preserved
as `godot/data/sculpt-ops.json` and `godot/data/sculpt-anchors.json` for the
next port, but are NOT applied to imported GLB meshes yet.

The terrain uses the saved source heights, source XY offsets and precise
polygonal cut algorithm. Plains cliff heightmap displacement is baked with
the original algorithm. The five ground textures and cliff body textures are
included, but current biome blending, missing alpha-detail decals and the
large hand-painted overlay are **not pixel-identical** to the Three.js editor.
Directional light, fog and shadows are early approximations for visual
inspection. Optimizing native colliders, full model sculpt reconstruction,
original material blending, and final player controls are separate stages.

Do not merge into `main` until source and visual parity are validated.

## Rebuild locally (only if changing the source JSON)

```bash
cd godot/tools
npm install --no-save pngjs@7.0.0
cd ../..
node godot/tools/bake-world.mjs
```

The GitHub workflow does this and checks import plus native scene boot. Never
reintroduce local browser storage as the authoritative world source.

## Step 2.1: native world in Godot's editor (without Play)

Open `res://scenes/main.tscn` and select the **3D** tab. The `World`
node now has an `@tool` script that reconstructs the terrain mesh, biome
shader and original GLB prefabs **in the editor**, using the same loader as
the runtime. Select `World` in the scene tree to find the Inspector toggle
**Vista previa** and its **Actualizar vista del mundo** button.

The mesh and GLB preview nodes are deliberately *transient* (no `owner`);
they will NOT be silently embedded into `main.tscn` when saving the scene.
Reopen `main.tscn` if another program changed source assets while the scene
was open, then click **Actualizar vista del mundo**. Use Godot's 3D orbit
controls to inspect the terrain. You may select `Camera3D` and enable
**Preview** to frame the level using the initial game camera.

In-game controls (character movement), procedural painting/gizmo editing,
spawn tools, and serialized inspector tools remain future milestones.
The Godot native editor preview does *not* save edits back to JSON yet.
